# Legacy Memory Cleanup — Design

## Problem

The `main.js` bundle (compiled from `src/`) uses only `Memory.creeps` and `Memory.pathing`. All other top-level Memory keys (`Memory.roomIntel`, `Memory.strategy`, `Memory.warPlan`, `Memory.spawnDemand`, `Memory.metrics`, `Memory._cache`, `Memory.debug`, `Memory.debugReport`) are written by old `.js` files that are no longer loaded. Over time these accumulate into wasted MB of `RawMemory`.

## Solution

### 1. Version-Namespaced Memory

All current-codebase data lives under `Memory[MEMORY_VERSION]` where `MEMORY_VERSION` is a constant string.

```
Memory.v1                  ← MEMORY_VERSION = 'v1', all current writes
  pathing
    terrain[roomName]

Memory.creeps              ← engine-managed, always kept
Memory.rooms               ← engine-managed (room.memory proxy), always kept
```

Engine-managed keys (`creeps`, `rooms`, `spawns`) and the current version key (`v1`) are whitelisted. Everything else at top level is legacy and deleted.

### 2. Migration on Version Bump

When `MEMORY_VERSION` changes (e.g. `'v1'` → `'v2'`), migration runs once:

```js
if (Memory.v1 && !Memory.v2) {
  Memory.v2 = Memory.v1   // reference copy — zero cost, carries all data
  delete Memory.v1        // v1 removed immediately
}
```

This runs **before any other write** in the loop, so `Memory.v2` is empty/uncontaminated. If a crash leaves partial `Memory.v2` data, `!Memory.v2` is false → migration skipped, v2 data (partial) persists and fills in naturally on next tick.

### 3. Cleanup Schedule

Runs at `Game.time % 100 === 0` in the loop.

```js
const ENGINE_KEYS = { creeps: 1, rooms: 1 }
const CURRENT_NS = 'v1'

function cleanLegacyMemory(): void {
  for (const key in Memory) {
    if (key === CURRENT_NS) continue
    if (ENGINE_KEYS[key]) continue
    delete Memory[key]
  }
}

function ensureMemoryNs(): void {
  if (!Memory[CURRENT_NS]) Memory[CURRENT_NS] = {}
}
```

Any key not in `[creeps, rooms, v1]` gets deleted. This automatically removes old legacy keys AND any previous version when `CURRENT_NS` changes after migration.

### 4. What Gets Moved

Immediate work — move the one current subsystem under the version namespace:

| Current path | New path |
|---|---|
| `Memory.pathing` | `Memory.v1.pathing` |
| `Memory.pathing.terrain` | `Memory.v1.pathing.terrain` |

Two write sites, one read site — all in `src/lib/TerrainMatrix.ts` and `src/main.ts`.

## Files Changed

- `src/lib/Memory.ts` — add `CURRENT_NS = 'v1'`, `ENGINE_KEYS`, `cleanLegacyMemory()`, `ensureMemoryNs()`
- `src/lib/TerrainMatrix.ts` — `Memory.pathing` → `Memory.v1.pathing`, `ensureMemoryNs()` call
- `src/main.ts` — call `ensureMemoryNs()` at loop top, `cleanLegacyMemory()` at %100, move dead-creep cleanup earlier
- `main.js` — compiled output (regenerated by rollup)
